# KorASR 实时漏句与精修幻觉排查

2026-09-27

## 一句话总结

当前运行的 ASR 确实是 GPU 上的 faster-whisper large-v3；实时漏句的主要可复现原因是通用韩语提示词诱发回放并被过滤，精修末尾假译文来自静音窗口仍被送去长稿 ASR。两条路径已修复并在本地测试服务重启。

## 这文档解决什么问题

把“模型太慢”“中途吞句”“静音精修胡编”和“是否做了降噪”拆开，记录证据、改动与尚未验证的效果。

- 测试数据库 `D:\AI\korAsr\data\korasr-local-test.db` 中会话 `2b60e095-134f-4220-9bf6-654f45e92042` 长 442 秒，仅保存 18 条实时段落；多个高 RMS 的最终 ASR 被记录为 `DROPPED (prompt echo)`。对同一原始 PCM 的 79–87、124–132、165–173 秒片段做只读 large-v3 离线对照：旧通用提示词使模型回吐“韩语讲课内容”，空提示词能得到实际谈话。未调用翻译 API。
- 用新空提示词与 6 秒切段只读回放该录音前 200 秒，得到 34 个非空段落；旧数据库保存 18 个。没有人工逐字稿，不能把新增的每段都认定为正确，但漏掉的语音内容得到了恢复。
- 同会话最后两段精修：chunk index 6（ID `59c99377-6fa1-49b3-ac98-dd007cb7cc66`）和 index 7（ID `5639eb29-bc02-4b69-a335-e9181ebb3c60`）。原件 `D:\AI\korAsr\data\raw-local-test\2b60e095-134f-4220-9bf6-654f45e92042.pcm` 中对应 360–420 秒、420–437 秒窗口 RMS 约 0.00265/0.00346，已无实时句；旧精修只要求音频长于 1 秒，因此在静音上识别出提示词与视频结尾套话并翻译。第 3 窗口虽没有实时句，但有明显语音能量，不能仅凭 DB 句数跳过。

## 本轮修改

1. `backend/asr/transcriber.py`：默认不向 Whisper 注入泛用课堂句；强制切段后保留语音和 VAD 连续状态；只有最后 1 秒有明确低能量谷底才在谷底切，否则在缓冲末尾切并保留重叠。最长缓冲从 8 秒改为 6 秒。`backend/ws/handler.py` 的临时识别间隔从 2.5 秒改为 1.5 秒，GPU 忙时仍跳过临时任务。
2. `backend/polish/translator.py` 与 `backend/ws/handler.py`：精修按 250 毫秒帧保守检测明确静音；跳过时推进 PCM 偏移和窗口序号，避免卡住后续语音。长稿文本过滤提示词回放、标点风暴、短重复与已知短幻觉，再决定是否调用付费翻译。原始 PCM 未修改，旧精修数据库记录未删除。
3. `frontend/src/views/ClassroomView.vue`：开课前可切换浏览器降噪和回声消除（默认请求开启），自动增益请求关闭；录制时展示浏览器报告的实际状态，便于同场景 A/B。此前代码只有 `getUserMedia({audio:true})`，服务器 VAD 不等于降噪，也没有神经人声增强。归档保存的是浏览器输出的音频。

## 验证与限制

- 后端 57 项回归测试、前端 2 项音频测试和生产构建通过；第 3 个精修窗口仍被保留，最后两窗被静音门控跳过。外网测试服务在同一 Tailscale 地址重启，使用 large-v3/CUDA、新配置和隔离测试数据库。
- 6 秒切段会增加每分钟 ASR/翻译请求数，可能增加 API 费用；实际端到端延迟、韩文词错率、跨段重复与吞句仍需真实课堂逐句核对。
- 浏览器降噪是否生效由设备和浏览器决定，页面会显示实际设置。没有加入未经 A/B 验证的重型人声增强模型，以免增加实时延迟或破坏训练用录音。
