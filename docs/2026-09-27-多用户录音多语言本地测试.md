# KorASR 多用户、录音与多语言迭代：本地测试说明

2026-09-27

## 一句话总结

本地代码已加入管理员创建账号、多用户课堂隔离、长期录音归档和六种翻译方向；先在本地验证实际语音效果，再决定是否部署。

## 这文档解决什么问题

说明这次迭代的行为、旧数据库如何迁移、怎样开始本地测试，以及哪些效果尚未经过真实课堂验证。

## 功能范围

| 功能 | 当前行为 |
|---|---|
| 账号 | 首位管理员由本机命令创建；管理员可在界面创建、禁用和重置其他账号；用户只能查看自己的课堂、字幕、术语表和录音。旧共享访问码不再用于登录。 |
| 并发 | 不同课堂可同时建立 WebSocket 和保存录音。单 GPU 的 ASR 推理仍以一个全局队列串行运行，实时延迟随并发数量变化，尚无实测容量数字。 |
| 录音 | 浏览器上传的 16 kHz 单声道 float32 PCM 原件按课堂 ID 保存在服务器；录音在停止或断线收尾时关闭并同步到磁盘。可按课堂下载原始 PCM 或流式转换的 16-bit WAV。 |
| 保留 | 长期保存，只有课堂所有者明确删除课堂时才清理录音；录制中或未完成收尾的课堂不能删除。低于 5 GiB 可用磁盘空间时显示提示。 |
| 翻译方向 | 韩语语音→中文、英语、俄语；中文语音→韩语、英语、俄语。每节课选择一次，字幕、精修、总结和导出使用该方向。 |
| 界面 | 按 [Apple Design skill](https://www.ui-skills.com/skills/emilkowalski/apple-design) 的响应、层级、空间一致、可访问性和减少动态效果原则重构桌面及移动布局。 |

> 数据库沿用 `ko_text`、`zh_text`、`ko_combined`、`zh_polished` 字段名以兼容旧记录；在新课堂中它们分别存放“源语言文本”和“目标语言文本”。界面和导出按实际方向标注。

## 本地测试前

1. 先备份 `D:\AI\korAsr\data\korasr.db`。首次运行新代码会为旧 SQLite 加入账号、语言和录音状态字段，并把旧课堂归给第一个管理员。迁移不删除原有课堂内容。
2. 在 `D:\AI\korAsr` 打开 PowerShell，执行：

   ```powershell
   python -m backend.admin create-user --username admin --admin
   ```

   命令会交互输入至少 12 字符的密码，不会把密码写在命令行。不要把密码发到聊天或提交到 Git。
3. 按项目原有方式安装 `requirements.txt` 并运行 `python start.py`。浏览器打开本机服务地址，以刚创建的账号登录。创建一节短课堂，先验证方向、录音、字幕、历史回看和下载，再试较长课堂。
4. 创建第二个普通账号，分别登录两种浏览器会话，确认彼此看不到对方的课堂与录音；两节课同时录制，观察字幕排队和磁盘剩余空间提示。

## 存储与调用费用

原始 PCM 每小时约 `16,000 样本/秒 × 4 字节 × 3,600 秒 = 230,400,000 字节`（约 220 MiB）。长期保留会持续占用服务器磁盘。下载 WAV 时逐块转换，不额外长期保存第二份录音。

本轮自动测试没有调用 Moonshot；你在本地实际说话测试时，每个稳定句和每个精修窗口会按现有服务逻辑触发付费翻译请求。多用户同时使用可能增加总请求量。

## 已验证与仍待验证

- 44 项自动测试通过，覆盖账号权限、旧库迁移、录音归档与下载、并发连接、六种语言方向的参数传递、翻译提示和失败收尾；前端生产构建及 Python 语法检查通过。没有真实 GPU 推理或付费翻译调用。
- 已用本地假数据检查桌面 1280 px 和手机 390/320 px 的课堂、历史、录音详情与管理员页面；未见横向溢出。
- 已对本地旧 SQLite 做只读内存副本迁移：课堂行数迁移前后均为 12，新字段齐全；原数据库未改动。
- 韩语和中文的实际识别准确率、英俄译文质量、两人以上并发时的端到端延迟，仍需你用本地课堂样本检验。
- 硬崩溃留下的 `recording_state=recording` 课堂会被保护，无法从界面删除。应先停服务，核对 PCM 完整性后再人工恢复状态；不要直接删录音文件。

## 麦克风已授权但没有字幕

2026-09-27 的一次本地反馈中，WebSocket 正常连接，但多节测试课堂的 PCM 均为 0 字节。截图显示“录音连接未就绪”：旧代码的连接 Promise 可能在 `onopen` 更新录音状态之前先完成，导致页面主动发送 `stop`。现已让 Promise 在录音状态就绪后才完成，并加了回归测试。`WinError 10054` 出现在连接关闭回调，不能据此判断麦克风权限。

音频采集现优先使用 AudioWorklet 发送固定 4096 样本块，失败时回退 ScriptProcessor；两条路径都没有音频块时会显示明确错误并停止空录音。

修改后先关闭旧服务并重新运行 `python start.py`，浏览器强制刷新页面（`Ctrl+F5`）再试。若仍提示没有音频块，在浏览器 `F12 → Console` 查找 `No microphone PCM blocks`，记录其中的 `mode`、`contextState` 和 `trackState`，再与 `logs/service.log` 对照。空的 PCM 文件会显示为不可下载，不代表录音成功。

## 静音时出现大量假字幕

本地录音 `D:\AI\korAsr\data\raw-local-test\a021df56-17c5-44f6-ab94-c207d1218ce6.pcm` 长 66.56 秒。安静区的 RMS 约 0.0055，高于旧版 0.005 的最终识别门槛；Silero VAD 只在开头判出 3 个语音块，旧代码却每到 8 秒无条件强制 ASR。Whisper tiny 因此生成韩文碎片和长串标点，且每条错误文本都尝试调用翻译。

现已只在 VAD 发现语音后安排临时或最终识别；没有语音时只保留 0.6 秒前置音频。标点占比异常或连续标点过长的识别结果会被丢弃。用上述原件只读离线回放后，最终 ASR 调用从反复触发降为 1 次，保留的临时和最终字幕均为 0 条；没有调用翻译 API。这一验证只针对该段静音录音，真实授课语音仍需测试。

同次及随后外网测试的日志显示 `moonshot-v1-auto`、`moonshot-v1-8k` 均返回 404／无权限。[官方模型列表](https://platform.kimi.com/docs/models)确认 `moonshot-v1` 系列已下线。使用现有中国区 Key 只读查询模型列表得到 `kimi-k2.6`、`kimi-k3` 和两个 K2.7 Code 模型，证明无须仅为此重新建 Key。当前翻译默认改用 `kimi-k2.6` 的非思考模式；模型名与中国区地址可通过 `MOONSHOT_MODEL`、`MOONSHOT_BASE_URL` 配置。不要把 Key 发到聊天里。

## Windows 上 Ctrl+C 卡在 Shutting down

曾有本地进程在浏览器连接重置后打印 `WinError 10054`，并停在 Uvicorn 的 `Shutting down`。Python 的 Proactor transport 在异常回调中可能跳过 socket 关闭和 server detach，进而卡住 Uvicorn 的 `server.wait_closed()`。`start.py` 现在在 Windows 使用 Selector 事件循环，并将优雅退出等待限制为 30 秒。修复前残留的进程不会自动变成新事件循环，需先确认其 PID 和状态后手动终止，再重新运行 `python start.py`。
