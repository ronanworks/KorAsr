# 挑战赛功能需求与差距（2026-11-23）

## 一句话总结

企划书（DSU AI 챌린지 2026，A 赛道）承诺的"现有原型"都已实现；"比赛期间开发"的四项都没开始。本文列出每项需求、验收标准和要动的代码，供在服务器上开发时对照。

## 这文档解决什么问题

企划书里的承诺分散在申请表和 7 栏企划书中。本文把它们整理成可验收的需求，标出现状和起点代码。设计背景见 `docs/2026-10-29-挑战赛企划与后续开发方向.md`。

## 比赛约束（所有需求都要遵守）

- 开发期间不得使用真实学生、教职员数据，测试用合成语音（申请表"서약"第 2 条）。
- 决赛演示时测外部 AI API 的 token 用量；为 0 则资源效率 10 分满分。
- 决赛是现场演示：一支麦克风讲课 → 几台手机显示不同语言字幕 → 课后出笔记和作业清单 → 确认外部 token 为 0。
- 企划书周计划：第 1 周 11/16–20 直播结构；第 2 周 11/23–27 本地模型；第 3 周 11/30–12/4 笔记、作业提醒、手机界面；第 4 周 12/7–11 合成语音测试、准备演示。

## R1 教室直播（一支麦克风 → 多终端）

**现状**：只有 `/ws/{session_id}`（`backend/main.py:114`）；一节课只认一个录音端（`backend/ws/handler.py` 的 `_claim_recording`）；语言计划由录音者按整节课设定。

**需求**

1. 一节课 = 一个采集端 + 任意多个只读观看端。
2. 采集端（教授或讲台 PC）开始课程后显示 QR 码和加入码；观看端扫码进入，比赛阶段不需要账号。
3. 观看端各选显示语言。识别每句只做一次；翻译只对"当前至少一个观看者选了的语言"做，结果发给选这种语言的所有观看者。
4. 观看端中途加入或断线重连，能补到本节课已有的字幕。
5. 采集端可以继续用现有的"个人设备麦克风"模式；保留一路补充输入的接口（TA、学生发言），去重和对齐可以后做。
6. 教授控制开始和结束；结束后观看链接只读。

**验收**：一台电脑当采集端，三台手机各选中、英、韩，同时显示；手机刷新后字幕不丢；新增一种语言时只多一路翻译。

**起点**：`backend/ws/handler.py` 拆采集端点与观看端点；新增房间/订阅管理；`frontend/src/stores/session.js` 加观看模式；加入码与过期时间存 `Session` 表或新表。

## R2 本地模型

**现状**：翻译、要点、提纲、总结全部走 Kimi；客户端是 OpenAI 兼容格式，`base_url` 可配（`.env.example` 第 8 行，`backend/translation/moonshot.py`）。

**需求**

1. 在 A8000 上起 OpenAI 兼容推理服务，模型候选只用许可证允许在韩国使用的：Seed-X-PPO-7B（OpenMDW，翻译）、Qwen3 系列（Apache 2.0，要点和总结）。**不用 Hunyuan-MT-7B**：许可证排除韩国。**不用 Gemma 3**：fp16 下出错。
2. A8000 是 Turing 架构：没有 bf16，没有 FlashAttention-2。先确认 fp16 或量化模型输出正常。
3. 显存与 Whisper large-v3、SenseVoice、说话人模型、korstudy 共用 48 GB；上线前测实际占用。
4. 翻译与要点可以分别指向不同模型（需要把 base_url / model 按用途分开配置）。
5. 提示词按本地模型重调；保留 Kimi 作为可切换的后备，但演示时关闭。

**验收**：演示流程中外部 API 调用为 0（日志可证明）；在合成测试集上，"听不清"率、〔?〕率、怪词抽查不明显差于 Kimi v2；单句翻译延迟中位数有记录。

**注意**：不在生产 GPU 上课时间做实验；切换前备份数据库。

## R3 AI 课堂笔记

**现状**：`backend/summary/generator.py` 有手动触发的总结（主要内容、关键概念、重要句子、待跟进）；`GlossaryTerm` 是手动录入。

**需求**：课程结束后自动生成整节总结；自动提取关键术语（原文 + 各语言释义）；观看端（含韩国学生）能看到并导出。

**验收**：结束一节合成课后 1 分钟内出现总结和术语表，无需手动点击。

## R4 作业与公告提醒

**需求**

1. 从教授的话里抽取作业、截止日期、考试范围。
2. 每条附原话和时间点，由学生确认（防误报）。
3. 列表显示，并可导出 .ics 日历文件；网页推送可选。

**验收**：在埋有 N 条作业通知的合成课上，找出的比例（召回率）有记录；每条都能跳回原话。

## R5 合成语音测试数据

**需求**

1. 写课堂脚本：韩语讲课为主，插入中文 TA 讲解、英语和俄语提问、若干作业通知。
2. 用 TTS 生成多说话人语音（本地模型优先，核对许可证）。
3. 两种输入：直接送入（模拟讲台麦克风）；音箱播放、手机远处录（模拟设备麦克风）。
4. 脚本即标准答案，存成可复用的评测集（不放真实数据）。

**分工**：뤄쯔이이 负责软件测试（企划书写明）。

## R6 测量

| 指标 | 方法 | 目标 |
|---|---|---|
| CER（Character Error Rate，字错误率） | R5 数据，手机麦克风对比讲台麦克风 | 记录对比 |
| 延迟 | 一句话说完到字幕和译文出现 | ≤ 3 秒 |
| 外部 token | 每小时课 | 0 |
| 单机教室数 | 多路采集并发压测；现有 Whisper 用全局 GPU 锁串行处理 | 记录上限 |

## 不做（本阶段）

R7（LTI、统一登录、App 推送）属于服务化阶段，学校选中后另行协商。
