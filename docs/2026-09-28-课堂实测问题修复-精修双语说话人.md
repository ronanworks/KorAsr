## 2. 改了什么

### 2.1 每句先判语言，再决定翻译方向

- `backend/asr/langid.py`：每个定稿句先做一次 Whisper 语言识别（一次 encoder 前向），只在会话的两种语言里选；短句需要更高把握才切换语言。
- 两种语言的概率都很低（笑声、噪声、视频原声，离线扫描里为 0.01–0.03）时直接丢弃。今天日志里的"감사합니다."类假字幕就出自这种片段。
- 韩语句 → 译成中文；中文句 → 译成韩语（`backend/languages.py`）。术语表对中文句反向使用。
- 新会话默认开启"自动识别双语"，建课时可以关掉；旧会话保持单向。

### 2.2 每分钟精修 + 本分钟要点 + 课堂脉络

`backend/polish/pipeline.py`、`backend/polish/translator.py`：

1. 窗口按音频时钟切，约 60 s 一段，边界总落在两句之间（只取已定稿并写库的句子）。
2. 窗口内的句子按"说话人 + 语言"合并成 run（≤ 28 s）。
3. 每个 run 用更长上下文复识别（开 VAD、逐句剔除循环输出），并和实时文本交叉校验：长度或相似度差异过大时沿用实时文本，降低复识别带进新幻觉的风险（不能完全排除）。
4. LLM 一次调用完成两件事：逐 run 翻译，外加 1–3 条"本分钟要点"。调用改为流式，限定 `max_tokens`，超时 45 s，重试 1 次；遇到"哈哈哈…"式失控输出会提前掐断。
5. 失败时沿用实时译文，状态标"沿用实时译文"。**窗口总是前进**，今天的卡死不会再出现。
6. 每 5 个窗口和下课时，用各分钟要点汇总一次"课堂脉络"（≤ 8 条）。

### 2.3 说话人区分

- 声纹模型：3D-Speaker CAM++（`models/speaker/`，28.3 MB，官方 sherpa-onnx release，sha256 已校验），CPU 推理，复用环境里已有的 onnxruntime，没有新装 pip 包。
- 每个定稿句提取声纹，做在线聚类，分配"说话人 N"；界面上点标签可以改名（如"教授""我"），改名也作用于精修、导出和 AI 总结。
- 模型缺失时自动关闭，转写不受影响。
- 阈值与评估：见 §3.3。

### 2.4 其他

- 时间戳改用音频采样时钟，与录音文件位置一致（旧版用服务器墙钟）。
- 中文幻觉黑名单（"请不吝点赞…""字幕由…提供"等），以及对"ㅋㅋㅋ""ㄱㄱㄱ"、长循环的检测。
- 导出（TXT/MD）和 AI 总结加入说话人、句子语言、每分钟要点和课堂脉络。
- 数据库只做加列迁移，不改旧数据。旧会话的 `bidirectional` 为 0。

### 3.3 说话人区分评估

原始输出在 `data/eval/2026-09-28/speaker/`（本地文件，不进 git）。

**有标注的公开样本**（sherpa-onnx release 里 3 个人的 14 段录音，`gt/gt_summary.json`）：

- 同一人余弦相似度 0.63–0.90，不同人 −0.10–0.43。
- 打乱顺序跑 50 轮：整段输入时 100% 的轮次恰好分出 3 人，平均准确率 98.1%。
- 切成 1.5–4 s 小段后：98% 的轮次分出 3 人，平均准确率 96.3%。

**今天的课堂**（`rec/d94a813b_report.json`，1127 个语音块，3182 s 语音，没有人工标注）：

| 说话人 | 语音时长 | 中位基频 | 出现范围 |
|---|---|---|---|
| 0 | 1677 s | 115 Hz（男声范围） | 03:13–86:43 |
| 1 | 1275 s | 242 Hz（女声范围） | 04:07–86:23 |
| 4 | 144 s | 225 Hz | 27:28–50:45 |
| 2 | 15 s | 348 Hz | 08:36–15:33 |
| 3、5 | 各 3 s 左右 | — | 大概率是误建 |

- 与同一批声纹的离线聚类一致率为 98.6%。
- 同一说话人内男女声基频混杂 2.6%，接近基频估计本身约 3% 的误差。
- 8.3% 的语音块没有标签，占语音时长 2.1%，多为不足 1 s 的短句。

结论：男声和女声分得开，但**音色相近的两个人（例如两位男性）可能被并成一个编号**，系统也不知道谁是教授。端到端测试里就出现过同一编号既说中文提问、又用韩语讲"所以我选了这个游戏"。每个说话人的试听片段在 `rec/samples/d94a813b_spk*.wav`，听一下就能判断编号是否对应真人。

- 阈值依据写在 `backend/speaker/tracker.py`：新建说话人至少要 2.0 s 实际语音、与已有说话人相似度 < 0.4；归入已有说话人需要 ≥ 0.5。
- 句子首尾约 0.6 s 静音不计入时长。按含静音的长度计算时，模拟里 8 个名额全被占满，一致率降到 95.9%。
- 延迟：6 s 片段在 CPU 双线程下平均 57 ms，p95 为 68 ms。`SPEAKER_THREADS=4` 时 p95 为 57 ms。
