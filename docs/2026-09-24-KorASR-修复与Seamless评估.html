这文档解决什么问题

记录本轮代码修复的范围、验证结果，以及 Seamless Communication 对课堂长程翻译的实际参考价值。没有真实课堂录音和人工对照译文，本轮不能给出准确率数字。

当前服务的两条管线

管线实现用户看到的结果
实时浏览器 16 kHz PCM → Silero VAD → faster-whisper → Moonshot 流式翻译数秒级草稿字幕；韩文先保存，中文稍后更新
精修原始 PCM 按最长 60 秒窗口重新 ASR → Moonshot 整段翻译，参考上一窗口的韩中对照语义分段的稳定译文；历史页可回看并导出

本轮修复

  • 停止或异常断开时等待所有 final 识别任务；先保存韩文，再更新中文。WebSocket 推送失败不再跳过数据库写入。
  • 移除前端 8 秒强制断开；收尾超过 30 秒只显示提示。离开录音页时停止麦克风并发送正常停止信号。
  • 历史详情和 TXT/Markdown 导出显示精修结果；收尾期间提示状态，完成后自动刷新；删除会话时清理实时句子、精修块和 PCM 文件。
  • API 与 WebSocket 增加访问口令和带期限的 HttpOnly Cookie。未设置随机口令时，数据接口拒绝访问。
  • 旧版源文件不再硬编码 Moonshot 密钥；服务启动前检查前端构建是否过期，必要时重新构建。
  • 精修参考上一窗口的译文，并明确只输出当前窗口内容；长稿 Whisper 的上一文本条件化改为可配置，默认关闭以降低循环幻觉风险。窗口最多读取 60 秒，停止时补处理积压窗口。

旧密钥仍存在 Git 历史中。必须在 Moonshot 平台吊销并替换该密钥；仅修改当前文件不能让已暴露的密钥失效。

Seamless 是否更好

问题现有证据判断
能否做韩语语音→中文字幕？论文语言表覆盖韩语语音输入和普通话文字输出；官方仓库提供 S2TT/流式方案。技术上值得试。
是否比 Whisper large-v3 + Moonshot 更准？论文主要用英语中心方向评测，未与本项目的韩→中管线直接比较。目前不知道。不能外推公开平均分数。
会自动解决长课堂上下文吗？论文长音频段落建议外部降噪、切片和组合。不会。断句、窗口衔接与术语管理仍需服务层处理。
部署到现有 Windows 服务？官方安装说明称 fairseq2 预编译包限 Linux x86-64 和 Apple Silicon；M4T v2 另有 Transformers 路径。先在隔离环境实验，不直接替换线上服务。
许可官方许可证：代码 MIT；M4T 与 Streaming 权重 CC BY-NC 4.0。研究对照可行，商业使用需另行审查。

怎样判断长程翻译是否真的改善

  1. 选同一批获准使用的真实课堂录音，人工标注韩文原句、关键术语及中文含义；保存录音与标注文件路径。
  2. 固定音频切分、硬件和计时方式，分别运行当前管线、SeamlessM4T v2 离线模式，以及需要时的 SeamlessStreaming。
  3. 分开统计韩语转写错误、中文遗漏/错译、术语跨窗口一致性和端到端字幕延迟；译文由懂韩中的评审盲评。
  4. 记录模型权重、代码提交、GPU、运行时长和每次 API 费用。没有这些记录，不报告“准确率提高了多少”。

验证与下一步

本地 11 项回归测试通过；Vue 生产构建通过；Python 代码通过语法检查。测试里的 ASR、翻译与精修均为 mock，没有调用 Moonshot，也没有在远端启动或更新服务。
